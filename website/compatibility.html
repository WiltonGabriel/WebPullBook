Four-Tier Classification

Website & Browser Compatibility

WebPullBook prioritizes structural DOM compatibility over domain-specific rules, combining dedicated layout adapters with a generic heuristic extractor, visual CSS selector picking, and tab rendering.

1. Verified & Tested (Verificados e Testados)

Sites and adapters tested end-to-end in live usage and covered by automated HTML regression fixtures in CI:

Site / Source Adapter ID Last Verified Verified Scope & Notes
Central Novel wp-lightnovel 2026-11-19 End-to-end tested (static SSR, zero SPA tabs): multi-volume detection, cover, synopsis, genres, and chapter fidelity.
Royal Road royalroad 2026-11-15 End-to-end tested (20 chapters): volume & chapter metadata, full synopsis, tags, cover, inline images, and hidden <style> watermark filtering.
Novel Mania novelmania 2026-11-15 End-to-end tested (20 chapters): paginated chapter API & multi-volume detection, full synopsis, genres, status, original cover, inline images, .sr-only heading cleanup, and footnote anchors.
Scribble Hub scribblehub 2026-11-19 End-to-end tested (index & direct chapter URL): AJAX full TOC, open-tab reuse, chronological ordering, metadata, inline images, and author note cleanup.

2. Added / Not Officially Tested (Adicionados, mas Não Testados Oficialmente)

Adapters or structural layouts implemented with unit fixtures, awaiting formal live verification across complete books:

Site / Structural Layout Adapter ID Current Status Notes
Madara-based platforms (.wp-manga-chapter, .reading-content) madara-theme Fixture-tested only Implemented with volume grouping and chapter extraction; pending official live-site testing checklist.
Other WordPress novel theme clones (.eplister, .ts-chl-collapsible, .epcontent) wp-lightnovel Structural match Shares the same WordPress novel DOM layout as Central Novel; awaiting individual live reports.

3. Potentially Compatible (Potencialmente Compatíveis)

Websites without a dedicated adapter that can be extracted using the generic parser and fallback tools:

Pattern / Layout Adapter / Mode How It Works
Static HTML chapter indexes, blogs & paginated lists (rel="next") generic-html Uses link-cluster scoring, prose density extraction (Innermost Node Wins), heuristic selector assistant, and the visual 🎯 Pick selector tool.
Sequential chapters without a TOC page generic-html ("Next Chapter" crawl) Crawls sequential "Next Chapter" links when starting directly from a prose chapter page.
JavaScript / SPA pages (React, Vue, Next.js) Tab rendering (renderWithTab) Extracts hydrated DOM via an open tab or a managed background worker tab when static HTML is an empty shell.
Open browser tabs Merge Tabs Compiles open HTTP/HTTPS tabs into a single anthology or standalone ebooks.

4. Not Compatible (Não Compatíveis)

Categories that cannot be extracted due to technical or access boundaries:

Pattern / Limitation Technical Reason
Proprietary DRM platforms Content is encrypted and inaccessible as standard DOM text nodes. WebPullBook does not circumvent DRM.
<canvas> or scrambled-image chapters Text is rendered purely as raster pixels without underlying HTML prose elements.
Locked paywalls without session access If your browser session cannot access a locked chapter, WebPullBook cannot access it either.
Hard non-bypassable anti-bot / CAPTCHA gates Automated requests pause when a challenge is detected until the user manually completes verification in a normal browser tab.

Browser Compatibility & Test Coverage

Difference between declared compatibility, automated CI verification, and manual validation:

Browser Family Minimum Version Declared Compatibility Verification Coverage (CI vs. Manual)
Google Chrome / Chromium Chrome 114+ Supported (MV3) Automated in CI: Playwright Chromium E2E test suite (loading unpacked extension, extracting series, previewing/editing, Library, exporting EPUB, and W3C EPUBCheck validation) + 56 Node.js unit/snapshot tests.
Microsoft Edge / Brave / Vivaldi Chromium 114+ Supported (MV3) Automated Engine + Manual UI: Uses the same Chromium Manifest V3 extension runtime tested in CI; verified manually via unpacked loading.
Mozilla Firefox Firefox 128.0+ Supported (MV3 Gecko) Static CI Checks + Manual Browser Validation: CI statically validates background.scripts, browser_specific_settings.gecko (Firefox 128+), and Firefox Origin header DNR rules. Live browser testing in Firefox is performed manually via about:debugging because Playwright's Firefox driver does not support loading unpacked WebExtensions via CLI flags.
