Compatibilidade de Sites e Navegadores

O WebPullBook prioriza compatibilidade estrutural de DOM em vez de regras presas a domínios, combinando adaptadores de layout com um extrator heurístico genérico, seletor visual CSS e renderização de abas.

1. Verificados e Testados (Verified & Tested)

Sites e adaptadores verificados de ponta a ponta em uso real e cobertos por fixtures automatizadas de regressão no CI:

Site / Fonte ID do Adaptador Última Verificação Escopo Verificado & Notas
Central Novel wp-lightnovel 2026-11-19 Testado de ponta a ponta (SSR estático, zero abas SPA): detecção de múltiplos volumes, capa, sinopse, gêneros e fidelidade de capítulos.
Royal Road royalroad 2026-11-15 Testado de ponta a ponta (20 capítulos): metadados de volumes e capítulos, sinopse completa, tags, capa, imagens internas e filtragem de marcas d'água ocultas em <style>.
Novel Mania novelmania 2026-11-15 Testado de ponta a ponta (20 capítulos): API paginada de capítulos e múltiplos volumes, sinopse completa, gêneros, status, capa original, imagens internas, limpeza de .sr-only e âncoras de notas de rodapé.
Scribble Hub scribblehub 2026-11-19 Testado de ponta a ponta (índice e URL direta de capítulo): sumário completo via AJAX, reaproveitamento de aba aberta, ordenação cronológica, metadados, imagens internas e limpeza de notas de autor.
NovelBin novelbin 2026-11-20 Testado de ponta a ponta (índice e URL direta de capítulo, 2 obras): hidratação automática de SPA via aba, pool reutilizável de abas, autor via JSON-LD e metadados completos, capa, limpeza de sr-only/título duplicado e XHTML de capítulos sem anúncios.

2. Adicionados, mas Não Testados Oficialmente (Added / Not Officially Tested)

Adaptadores ou layouts estruturais implementados com fixtures unitárias, aguardando validação ao vivo em obras completas:

Site / Layout Estrutural ID do Adaptador Status Atual Notas
Plataformas baseadas em Madara (.wp-manga-chapter, .reading-content) madara-theme Testado via fixture Implementado com agrupamento por volumes e extração de capítulos; aguardando checklist oficial de teste em site ao vivo.
Outros clones de temas WordPress de novels (.eplister, .ts-chl-collapsible, .epcontent) wp-lightnovel Compatibilidade estrutural Compartilha a mesma estrutura DOM de temas WordPress do Central Novel; aguardando relatos individuais em uso real.

3. Potencialmente Compatíveis (Potentially Compatible)

Sites sem adaptador dedicado que podem ser extraídos usando o parser genérico e as ferramentas de ajuste:

Padrão / Layout Adaptador / Modo Como Funciona
Índices HTML estáticos, blogs e listas paginadas (rel="next") generic-html Usa pontuação de clusters de links, extração por densidade de prosa, assistente heurístico de seletores e seletor visual 🎯 Apontar.
Capítulos sequenciais sem página de sumário generic-html (rastreamento "Próximo Capítulo") Rastreia automaticamente links sequenciais de "Próximo Capítulo" / "Next Chapter" ao iniciar em um capítulo.
Páginas JavaScript / SPA (React, Vue, Next.js) Renderização via aba (renderWithTab) Extrai o DOM hidratado via aba aberta ou aba auxiliar em segundo plano quando o HTML estático é uma casca vazia.
Abas abertas do navegador Juntar Abas (Merge Tabs) Compila abas HTTP/HTTPS abertas em uma única coletânea ou em livros separados.

4. Não Compatíveis (Not Compatible)

Categorias que não podem ser extraídas por limites técnicos ou de acesso:

Padrão / Limitação Motivo Técnico
Plataformas com DRM proprietário O conteúdo é criptografado e inacessível como texto DOM padrão.
Capítulos em <canvas> ou imagens embaralhadas O texto é renderizado apenas como pixels de imagem sem nós de texto HTML.
Paywalls fechados sem acesso na sessão A sessão do navegador não tem acesso a capítulos bloqueados por paywall.
Barreiras anti-bot / CAPTCHA estritas Requisições automatizadas ficam bloqueadas até que o usuário conclua a verificação manualmente em uma aba normal.

Compatibilidade entre Navegadores & Cobertura de Testes

Diferença entre compatibilidade declarada, verificação automatizada em CI e validação manual:

Família de Navegador Versão Mínima Compatibilidade Declarada Cobertura de Verificação (CI vs. Manual)
Google Chrome / Chromium Chrome 114+ Suportado (MV3) Automatizado no CI: Suíte E2E com Playwright Chromium (carregando a extensão descompactada, extraindo obras, pré-visualizando/editando, Biblioteca, exportando EPUB e validando com W3C EPUBCheck) + a suíte nativa de testes unitários e snapshots em Node.js.
Microsoft Edge / Brave / Vivaldi Chromium 114+ Suportado (MV3) Motor Automatizado + UI Manual: Utiliza o mesmo motor Chromium Manifest V3 testado no CI; validado manualmente via carregamento sem compactação.
Mozilla Firefox Firefox 128.0+ Suportado (MV3 Gecko) Assinado no AMO + Validação Estática no CI: Publicado como extensão assinada no Firefox Add-ons (AMO) com data_collection_permissions declarado como nenhuma coleta. O CI valida estaticamente background.scripts, browser_specific_settings.gecko (Firefox 128+) e a regra DNR do cabeçalho Origin, enquanto o teste interativo de interface no Firefox é feito manualmente via about:debugging.
