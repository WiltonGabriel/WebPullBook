Privacy Policy & Permissions Disclosure

This document explains what runs locally in the WebPullBook browser extension, how network requests to target websites work, what data is stored on your device, why each Manifest V3 permission is declared, and how this public website measures aggregated visits with GoatCounter.

Summary

The WebPullBook browser extension does not collect, transmit, rent, or sell personal data, browsing history, or usage telemetry. The extension operates no backend servers and includes no tracking or analytics scripts: all content extraction, XHTML sanitization, image processing, and ebook packaging happen locally on your device.

Separately, this public documentation website (wiltongabriel.github.io/WebPullBook) uses GoatCounter, an open-source, cookieless web analytics tool, strictly to count aggregated page views without cookies, persistent identifiers, or personal user profiles.

1. Local Processing vs. Origin Network Requests

Within the WebPullBook browser extension, third-party data transmission does not occur; network traffic consists solely of user-initiated downloads from origin websites:

  • Local Processing: DOM parsing, HTML-to-XHTML sanitization (HtmlSanitizer), Canvas image resizing, and ZIP/EPUB archive compression (CompressionStream) run in your browser's local memory.
  • Direct Requests to User-Chosen Websites: When you load a series URL, check your saved Library for new chapters, or export an ebook, your browser sends standard HTTP/HTTPS requests directly to the target website (and its image CDNs) to download those chapters and illustrations.
  • No Intermediate Servers: Requests do not pass through any proxy or server operated by WebPullBook.

2. Browser Sessions, Cookies & Image Fallbacks

WebPullBook does not read, store, or export your passwords, cookies, or authentication tokens:

  • Standard Browser Session Context: When fetching chapter pages or images from a target site, the browser's fetch() API uses credentials: 'include' by default so pages already accessible in your current browser session load normally.
  • Anonymous Image Retry: If an image host or CDN bucket rejects credentialed requests or Referer headers (for example, returning HTTP 401/403 or CORS errors), fetchImageBytes retries the image request with credentials: 'omit' and referrerPolicy: 'no-referrer'.
  • Cover URL Normalization: When a cover image URL points to a resized WordPress Jetpack proxy (i0.wp.com), toHighResCoverUrl resolves the direct origin image URL to fetch the original cover.

3. What Data Is Stored Locally on Your Device

All persistent extension settings and caches remain inside your local browser profile (never synced via chrome.storage.sync) and can be cleared at any time:

Storage Mechanism Key / Database Name Purpose Retention & User Control
chrome.storage.local wpbOptions Saves global UI preferences (language, theme, Reader Profile, typography, output folder template, Safe Mode settings). Per-site CSS selectors are excluded from global options automatically. Kept until you click Reset All Advanced Options or uninstall the extension. Can also be exported/imported as a local JSON file.
chrome.storage.local wpbLibrary Stores series you save to your Library (title, author, cover URL, source URL, chapter count, and known chapter URLs) so you can check for new chapters. Kept until you click Remove on a Library card or uninstall the extension.
chrome.storage.local wpbDomainRules Stores custom CSS selectors and SPA rendering rules saved for specific domains via Save for Domain. Kept until you delete the domain rule chip in Advanced Options.
IndexedDB WebPullBookCache Temporarily caches sanitized chapter XHTML and active download sessions so interrupted downloads can resume without re-fetching chapters. Capped at 64 MB with automatic LRU eviction. Expires after the configured TTL (default: 7 days; can be set to Cache disabled or cleared via Clear Cache).
IndexedDB WebPullBookHandles Stores the optional local folder permission handle (FileSystemDirectoryHandle) when you choose a custom output folder on your computer. Kept until you click Use Downloads or clear browser extension data.
localStorage wpb-color-scheme Caches the selected UI theme token (light, dark, sepia, midnight) to avoid a white flash on workspace load. Cleared when switching back to System theme or uninstalling the extension.

4. Technical Justification of Manifest V3 Permissions

WebPullBook declares the following browser permissions in manifest.json:

Permission Category Technical Justification & Feature
tabs permissions Reads the active tab's URL when opening the workspace from the toolbar icon, lists open browser tabs in the Merge Tabs modal, and manages the single reusable background tab (TabRenderPool) when rendering JavaScript/SPA pages.
scripting permissions Captures the already-rendered live DOM from the originating tab, extracts hydrated HTML in SPA/JavaScript Tab Mode, and runs the interactive Pick CSS selector overlay when triggered by the user.
storage permissions Persists user preferences (wpbOptions), tracked Library series (wpbLibrary), and saved per-domain CSS rules (wpbDomainRules) locally in chrome.storage.local.
downloads permissions Saves generated .epub, .html, .md, .txt, and diagnostic log files into your computer's Downloads folder (including custom relative subfolders like Downloads/WebPullBook/<Title>/).
declarativeNetRequestWithHostAccess permissions Used for temporary session-scoped rules: on Firefox, rule ID 1 removes the Origin: moz-extension:// header so cross-origin chapter/image fetches are not rejected by server CORS checks; session rules 100..119 attach standard navigation headers when required by protected hosts, and ref-counted session rules 120..129 supply temporary same-origin Referer fallbacks only when hotlink-protected images fail anonymous retries.
https://*/* & http://*/* host_permissions WebPullBook is a general-purpose Web-to-EPUB converter meant to work on any website, blog, documentation site, or local archive selected by the user. Because target domains are chosen by the user at runtime, HTTP/HTTPS host access is required to fetch chapter HTML and illustrations on demand.

For Mozilla Firefox Add-ons (AMO), manifest.json also declares data_collection_permissions: { "required": ["none"] } under browser_specific_settings.gecko, reflecting that WebPullBook collects or transmits no user data.

5. Public Website Analytics (GoatCounter)

While the WebPullBook browser extension performs zero analytics or telemetry, the public documentation pages hosted on GitHub Pages use GoatCounter for lightweight, privacy-preserving visit counting.

Purpose & Scope

  • Website Only (Never the Extension): GoatCounter runs strictly on the public documentation website (wiltongabriel.github.io/WebPullBook/ and /pt/). It is never loaded inside the WebPullBook browser extension or during ebook extraction.
  • Purpose: Aggregated page-view counts help maintainers understand overall visits and see which guides, documentation pages, and languages (English or Portuguese) are most useful.
  • No Tracking Profiles or Ads: Metrics are strictly aggregated and non-identifiable. No data is used for advertising, cross-site tracking, behavioral profiling, or commercial sharing.
  • Static Website Local Storage: Separately from GoatCounter, this website only stores your optional theme choice (wpb-site-theme in localStorage) and a 10-minute cache of the latest public GitHub release version in sessionStorage.

Data Processed & Privacy Protections

  • Aggregated Metrics Processed: Visited page path and title, referrer URL, browser name/version and operating system (derived from the User-Agent header and stored only as aggregate counts without keeping raw User-Agent strings), approximate country/region (derived transiently from the IP address without saving raw IP addresses), screen width, and browser language.
  • Unique Visits Without Cookies: To count unique daily visits without tracking individuals, GoatCounter computes a temporary, non-reversible hash in memory from the site, IP address, User-Agent, and a daily rotating random salt. This hash remains briefly in server memory (up to 8 hours) and is never written to the database.
  • No Cookies or Consent Banner Needed: GoatCounter sets no cookies, uses no localStorage, and creates no persistent user identifiers, so no cookie consent banner or modal is needed. See GoatCounter's Privacy Policy for technical details.
Contact & Security Reporting

For privacy questions, open an issue on GitHub Issues. To report a security vulnerability (such as an HTML sanitization bypass or CSP issue), use GitHub Private Security Advisories as documented in SECURITY.md.
