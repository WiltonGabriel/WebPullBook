Contributing to WebPullBook

WebPullBook was created and is maintained by Wilton Gabriel, and is open to community contributions under the GNU AGPLv3 (AGPL-3.0-or-later). With native ES modules, zero runtime dependencies, and zero build step, you can inspect, edit, and run the entire extension straight from a cloned folder.

Part 1 — How WebPullBook Works Under the Hood

Before diving into a change, here is how the repository is organized, how web pages turn into ebooks in five stages, and which architectural rules protect quality.

Directory / File Responsibility
src/background/ MV3 service worker / event script: opens the workspace tab with sourceTabId, maintains Firefox declarativeNetRequest Origin rules, and cleans up orphaned session rules (100..129).
src/core/ Shared engine modules: BaseParser, parser-helpers.js, net-fetcher.js (active-tab capture, TabRenderPool, assertSafeHttpUrl), HtmlSanitizer, xhtml-serializer.js, image-processor.js, epub-builder.js, cache-store.js, and native zip.js.
src/parsers/ ParserRegistry (single-pass matchScore competition), GenericHtmlParser (Universal Smart Extractor), and shared structural adapters registered in src/parsers/index.js.
src/exporters/ Polymorphic BaseExporter implementations (epub, html, md, txt) exporting clean files through exporterRegistry.
src/workspace/ Modular UI controllers, READER_PRESETS, 4 CSS themes, PT/EN locale bundles (locales/en.js, locales/pt.js), and icons.js (strict createElementNS SVGs).
docs/ & scripts/ Single-source documentation (COMPATIBILITY.md, READER_PRESETS*.md, docs/pt/) and Node.js stdlib scripts (check.mjs, sync-website.mjs, verify-website.mjs).
tests/ & website/ node:test suites with anonymized HTML fixtures, W3C EPUBCheck verification, Chromium/Firefox MV3 E2E suites, and the bilingual GitHub Pages site.

Stage 1–2: Discovery & Collection

ParserRegistry scores the loaded DOM (from active tab or fetch). If an empty JS shell arrives, loadSeriesWithParser() falls back to TabRenderPool. BaseParser.collectAllChapters() collects chapters and normalizes volumes.

Stage 3: Download & Whitelist Hygiene

AdaptiveRateLimiter coordinates Safe Mode pacing and Retry-After delays, while HtmlSanitizer + serializeChapterXhtml() strip scripts/ads/decoys and emit valid XHTML 1.1 or XHTML5 + pop-up footnotes.

Stage 4–5: Media, Cache & ZIP32

fetchImageBytes() checks binary magic bytes and deduplicates assets by content hash; WebPullBookCache persists completed chapters in IndexedDB; exporterRegistry + createZipBlob() package final files cleanly.

Zero Runtime Dependencies

Keep dependencies empty in package.json, reuse helpers in src/core/parser-helpers.js, build UI icons only via document.createElementNS, and keep exact PT/EN key parity in src/workspace/locales/.

Single Sources of Truth

Update compatibility only in docs/COMPATIBILITY.md (site names only—never domain URLs) and run node scripts/sync-website.mjs twice rather than hand-editing synced website tables.

Zero Access Bypass

Never attempt to circumvent DRM, paywalls, or anti-bot CAPTCHAs. When Cloudflare or HTTP 429/503 gates appear, trip the circuit breaker so users verify manually in a normal tab.

Part 3 — Step-by-Step Contribution Guides

Each tutorial below walks through the exact files, validation rules, and issue templates used in WebPullBook:

1. Developing & Adding a Parser Adapter (src/parsers/)

Back to ways to help ↑

Create a new parser only when a shared layout, paginated JSON API, or AJAX endpoint cannot be extracted reliably by Universal Smart Extractor (generic-html). Prefer shared structural adapters over site-locked selectors.

  1. Create your adapter class: Add a module in src/parsers/ extending BaseParser (reuse utilities in src/core/parser-helpers.js instead of duplicating JSON or DOM helpers).
  2. Register in order: Import and register an instance inside src/parsers/index.js before genericHtmlParser (GenericHtmlParser acts as the catch-all fallback).
  3. Add anonymized fixtures & unit tests: Save anonymized HTML/API samples under tests/fixtures/ (never include private user data or real personal credentials), record expectations in tests/fixtures/snapshots.json, and add assertions in tests/parsers.test.js.
  4. Document & validate: Add the layout entry under tier Added / Not Officially Tested (or Verified & Tested with live E2E coverage) in docs/COMPATIBILITY.md, run node scripts/sync-website.mjs twice, and run npm run lint && npm run lint:biome && REQUIRE_EPUBCHECK=1 npm test.
Request Shared Theme / Adapter Support Request Dedicated Site Parser

2. Improving Universal Smart Extractor, Sanitizer & Core Pipeline

Back to ways to help ↑

Improvements to shared heuristics often unlock dozens of unlisted websites at once without adding per-site adapters:

  • Generic Discovery & Scoring: Edit src/parsers/generic-html.js (link-cluster heuristics, Innermost Node Wins prose density scoring, and sequential "Next Chapter" matching) or shared hooks in src/core/base-parser.js.
  • HTML Sanitization & XHTML Serialization: Update src/core/sanitizer.js and src/core/xhtml-serializer.js for new hidden CSS decoy tricks, lazy image attributes, or EPUB 2/3 XML edge cases.
  • Test-First Rule: Always add a failing regression test first in tests/parsers.test.js, tests/sanitizer.test.js, or tests/epub-validation.test.js and verify with REQUIRE_EPUBCHECK=1 node --test tests/*.test.js. Need private live-site E2E scripts while iterating? Keep them strictly inside the gitignored .local-e2e/ folder.

3. Testing Websites & Updating the Compatibility Matrix

Back to ways to help ↑
  1. Test with default settings first: Try loading the index URL and at least a couple of chapters in WebPullBook; check metadata, volumes, cover, inline images, and clean XHTML output.
  2. Know the four tiers: Verified & Tested requires real live E2E verification plus regression fixtures in tests/fixtures/; sites tested manually by layout can use Added / Not Officially Tested or the Compatibility issue form.
  3. Follow the no-URL rule: When opening a PR updating docs/COMPATIBILITY.md, write only the site/layout name—never domain URLs or links—then run node scripts/sync-website.mjs twice to update this website automatically.
Submit Compatibility Matrix Update

4. Reporting Bugs & Extraction Errors

Back to ways to help ↑
  1. Gather workspace logs first: Open the Logs tab inside WebPullBook right after the error occurs and click Download Log (or Copy Log).
  2. Capture helpful context: Include your browser name, WebPullBook version, selected export format/profile, the affected layout structure (CSS classes of the chapter list or text container if known), and attach any diagnostic snippet without personal cookies or tokens.
  3. Security flaws go private: If you find an XSS sanitization bypass, path traversal, or CSP issue, report it privately via GitHub Private Security Advisories instead of public issues.
Open Bug Report Issue

5. Suggesting Features & Validating on Real E-Readers

Back to ways to help ↑

Real-device feedback is invaluable because firmware converters behave differently across e-reader generations:

  • E-Reader & App QA: Test generated .epub files with Kindle (both Send to Kindle EPUB 2 and Calibre USB KFX/AZW3), Kobo/KePub, PocketBook, Tolino, Apple Books, and Thorium Reader. Verify cover display, nested volume TOC, pop-up footnotes, and font styling.
  • Propose Enhancements: Share concrete use cases and expected behavior via our feature template—keeping WebPullBook's quiet, minimal interface and zero runtime dependency philosophy in mind.
Open Feature Request Issue

6. Improving the Website, Documentation & Translations

Back to ways to help ↑
  • Extension Localization: Maintain strict key parity between src/workspace/locales/en.js and src/workspace/locales/pt.js (plus _locales/en/ and _locales/pt_BR/), zero emojis in locale strings, and verify with node scripts/check.mjs.
  • Docs & Website Sync: Update English docs alongside optional mirrors in docs/pt/ and keep both website/*.html and website/pt/*.html aligned. Never hand-edit synced tables or footer versions—run node scripts/sync-website.mjs twice and verify with node scripts/verify-website.mjs.
Report Website Issue Report Documentation Issue
